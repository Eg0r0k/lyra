## Deferred doc requirements (for T-25 README overhaul)

- **Fades section**: document that `fadeOut()` (without `fadeOutAndPause`/`fadeOutAndStop`) leaves the fade multiplier at 0 while playback continues; raising `volume` will NOT restore sound. Recovery is `fadeIn()` (or use the And-Pause/And-Stop variants). Note the new `player.fadeMultiplier` getter (0..1) alongside `isFading`, and that fade and volume are independent multipliers (T-10).
- **Normalization section** (T-12): document the per-track workflow — loudness metadata is cleared on every `load()`, so the pattern is `await load(src)` → `setLoudnessMetadata(meta)`. Note the `loudnessNormalization.retainMetadataAcrossLoads` opt-out (default `false`) for apps that reuse one measurement across tracks.
- **Source handlers section** (T-14/F-37): document `Player.registerHandler(handler)` — prepend = highest priority (broad `canHandle` overrides HLS/everything, so keep it narrow); caller **owns** the handler (player never disposes a registered handler; don't share a stateful one across concurrent players); no `unregisterHandler`. Plus the `ISourceHandler` lifecycle (constructed once, `prepare` per load, `reset?()` between loads, `dispose` by the owner). This is the API the audit flagged as missing from the README.
- **Live streams section** (T-15): the verification pattern is **`player.isLive`**, NOT `duration === Infinity`. Warn explicitly: binding a progress bar to `duration` breaks on hls.js live — hls.js reports a **finite, growing sliding-window** duration (only native HLS/Safari reports `Infinity`), so a naive `currentTime / duration` bar creeps upward instead of showing "live". Consumers MUST branch on `isLive` first: when live, hide/replace the scrubber (progress is always `0`) and use `seek()` (clamps to the seekable window, no-op when empty) rather than absolute positions.
- **Playback rate / pitch section** (T-23): document `preservesPitch` option (default `true`), `Player.setPreservesPitch(v)` (applies live to the html5 element and to future loads), `player.preservesPitch` (intent) and `player.canPreservePitch` (reflects the active strategy: html5 feature-detected true, webaudio false until a T-24 time-stretch plugin). Note quality boundaries (usable ~0.5x-2x; extremes degrade/mute) and that webaudio shifts pitch with rate (logs one warning) until T-24.
- **HLS quality section** (T-16): `setQuality(level)` returns `boolean` (false = invalid index, no-op) and does **not** emit `qualitychange` synchronously — the real, engine-selected level arrives asynchronously via `qualitychange` once hls.js switches (including ABR after `setQuality(-1)` auto). Also: `hlsConfig` accepts any hls.js option (typed `Partial<HLSConfig> & Record<string, unknown>`) — arbitrary keys pass straight through to the `Hls` constructor.
- **Timeupdate cadence / seek section** (T-18): `timeupdate` fires ~4/s (250 ms timer) in the **active** tab for both strategies (was 60 Hz rAF for webaudio). In a **background** tab browsers throttle timers to ~1/s, so `timeupdate` fires less often there — but the reported values stay accurate (`currentTime` derives from `ctx.currentTime`, an audio clock unaffected by throttling); only the emit frequency drops. For smooth animation loops read `player.currentTime` on demand (real-time) rather than timing off `timeupdate`. Note `seeked` fires when the seek actually completes (html5: async native event; webaudio: synchronous) and no longer emits a spurious pause/play pair on webaudio seek. Changelog: cadence change is a behavioral note (non-breaking).
- **Shared AudioContext section** (T-19): document `PlayerOptions.audioContext` — inject an existing context to share across players (iOS context limits / shared unlock state). The player uses it as-is (`latencyHint` ignored), never closes it on `dispose()` (caller owns lifecycle; only player-created contexts are closed), throws `PLAYBACK_FAILED` if the injected context is already closed, and — unlike the original plan — does NOT take over `onstatechange` (registers via `addEventListener`, so the caller's own handler is preserved).
